# 固定服务器 IP（一次性配置）

> 目的：让部署机的 IP 永远不变，这样 App 里填一次地址就**再也不用改**。
> 适用：**目标部署机默认 Linux**（本方案的主路径）；只有备用 Windows 部署机才看 6.6。
> 亮点：**不需要提前知道现场网段**——到现场用 DHCP 连上后，把"它拿到的那个 IP"原样钉住即可（见第三节）。

---

## 一、三种做法，按推荐顺序

| 做法 | 要改哪里 | 需要谁 | 备注 |
|---|---|---|---|
| **① 服务器上一键设置静态 IP** | 服务器（1 个配置文件） | 你自己（有 sudo） | ⭐ 推荐，本项目提供脚本 |
| ② 路由器 DHCP 保留 | 路由器后台 | 路由器管理员密码 | 不改电脑，最稳；拿不到密码就用 ① |
| ③ 什么都不改 | — | — | 用 App 内「自动搜索服务器」+ 必要时手填 |

---

## 二、一键脚本用法（推荐）

脚本位置：`tools/set-static-ip.sh`（在服务器上进入项目目录执行）

```bash
# 1) 先看当前网卡 / IP / 网关，确认信息
ip -br addr
ip route

# 2) 挑一个没人用的 IP（ping 无响应即可）
ping -c 2 192.168.1.123

# 3) 执行（最简用法，网关/网卡/DNS 会自动检测）
cd /home/dingyou/cotton/cotton
sudo bash tools/set-static-ip.sh -i 192.168.1.123

# 需要显式指定时：
sudo bash tools/set-static-ip.sh -i 192.168.1.123 -g 192.168.1.1 -n eth0
```

> 💡 **不需要提前知道现场网段**：`-i` 的值由**现场**决定，脚本会自动推导网卡、网关、掩码前缀、DNS。
> 也就是说"换一个网络（`10.x.x.x` / `192.168.0.x` / 其他）该填什么"这件事，**到现场看一分钟就能定**，
> 不必也不应该提前写死。具体做法见第三节。

脚本会自动完成：

1. 检测网卡、网关、掩码；
2. **ping 目标 IP 做冲突检测**（被占用就直接中止，不冒险）；
3. 备份原配置 → 写入 `/etc/netplan/99-cotton-static.yaml`；
4. `netplan generate` 校验语法；
5. 默认走 **`netplan try`**：120 秒内不确认会**自动回滚**，不会把你关在 SSH 门外；
6. 打印 `ip addr`、网关/外网连通性，以及最终要填进 App 的地址。

> 远程操作**一定不要加 `-y`**（那会直接 `apply`，改错就断连）。改完确认能重连后再按回车。

CentOS / RHEL 等没有 netplan 的系统，脚本会自动改用 `nmcli`；两者都没有时会打印手动 `ifcfg-网卡` 的改法。

## 三、不知道现场网段怎么办（现场定 IP 的推荐流程）

**结论：先到现场、用 DHCP 连上、看它拿到什么，再"把那个 IP 钉住"。** 全程不需要提前猜网段。

### 3.1 三条硬道理（为什么不用提前知道）

| # | 事实 | 依据 |
|---|---|---|
| 1 | 静态 IP 必须和现场路由器**同网段**，这个信息只有现场才有 | `ip -br addr` / `ip route` |
| 2 | 脚本的 `-i` 是任意值，网关/掩码由**当前网络**自动推导，没有硬编码 IP | `tools/set-static-ip.sh` |
| 3 | 后端端口映射**不绑定具体 IP**（`"${BACKEND_PUBLIC_PORT:-8088}:8080"`），换网段不用改配置、不用重新部署 | `docker-compose.yml`、`docker-compose.linux.yml` |

补充：App 侧也不依赖网段——「自动搜索服务器」会取手机自身 IP 推导所在 `/24` 再扫 `8088`（`apps/android/src/services/serverConfig.ts`），
手机网段没命中还会兜底扫 `192.168.1.x`、`192.168.0.x`。所以**通用版 APK 与 IP 完全解耦**，出门前发通用版即可。

### 3.2 现场六步（约 10 分钟）

| 步骤 | 命令 / 操作 | 预期结果 |
|---|---|---|
| 1 | 服务器接上现场网络，**保持 DHCP**，执行 `ip -br addr` 与 `ip route` | 拿到一个现场 IP（如 `10.20.30.77/24`）和网关（`10.20.30.1`） |
| 2 | 决定用哪个 IP：**推荐直接用第 1 步拿到的那个 IP**；想换就 `ping -c 2 <候选IP>` 确认无人应答 | 候选 IP 无响应 |
| 3 | `cd 项目目录 && sudo bash tools/set-static-ip.sh -i <第2步的IP>` | 脚本打印网卡/网关/掩码，并做 `netplan try` |
| 4 | 出现确认提示时**另开一个窗口** `ssh`/`ping` 测试，通了再回原窗口回车（不按则 120 秒自动回滚） | 新 IP 可连 |
| 5 | `ip -4 -br addr show dev <网卡>`、`curl http://127.0.0.1:8088/health`、`sudo docker compose ps` | IP 已固定、后端与容器健康 |
| 6 | 手机 App：**我的 → 系统设置 → 服务器地址 →「自动搜索服务器」**（或手填 `http://<第2步的IP>:8088`） | 提示设置成功 |

> 第 3 步若填的正是当前 IP，脚本会提示「目标 IP 与当前 IP 相同，仅把配置方式从 DHCP 改为静态」——这是**零冲突风险**的做法。
> 唯一缺点是它可能落在路由器 DHCP 池里，长期看建议改用「路由器 DHCP 保留」或换到池外的地址。

### 3.3 与一键部署脚本的先后顺序

两个脚本可以互相独立，顺序也不敏感，推荐 **先定 IP 再部署**：

```bash
# Linux 部署机（顺序：先 IP 后部署）
sudo bash tools/set-static-ip.sh -i <现场IP>
chmod +x deploy-lan.sh && sudo ./deploy-lan.sh     # 会问两次，直接回车
hostname -I                                        # 核对 IP，这个值就是要填进 App 的
```

```powershell
# Windows（备用方案）：deploy-lan.ps1 第 1.5 步自带「静态 IP 提醒」
#   会打印当前 IP 并说明"电脑重启后 IP 变了手机就连不上"，让你确认 [Y/n]；
#   选 n 会直接退出，让你先去设静态 IP（见第六节 Windows 做法）。
.\deploy-lan.ps1
ipconfig                                            # 核对 IPv4，这个值填进 App
```

> 反过来（先部署再改 IP）也可以，但改完 IP 后记得：App 里的地址要同步改一次，或点「自动搜索服务器」重扫。

## 四、手动方式（不想跑脚本时）


Ubuntu（netplan）——新建 `/etc/netplan/99-cotton-static.yaml`：

```yaml
network:
  version: 2
  ethernets:
    eth0:                                # 换成你的网卡名
      dhcp4: false
      addresses: [192.168.1.123/24]
      routes:
        - to: default
          via: 192.168.1.1               # 换成实际网关
      nameservers:
        addresses: [114.114.114.114, 8.8.8.8]
```

```bash
sudo chmod 600 /etc/netplan/99-cotton-static.yaml
sudo netplan try          # 远程操作务必用 try（可自动回滚）
ip -br addr               # 确认生效
```

## 五、验证与收尾

```bash
ip -br addr                                  # IP 已固定
curl http://127.0.0.1:8088/health            # 后端正常
sudo docker compose ps                       # 容器健康
```

App 内（一次性）：我的 → 系统设置 → 服务器地址 → 填 `http://192.168.1.123:8088` → 保存并测试连接。

**恢复 DHCP**：

```bash
sudo rm /etc/netplan/99-cotton-static.yaml
sudo netplan apply
```

## 六、提醒与自检清单（出发前 / 现场务必先看）

### 6.1 安全：别把自己关在门外

- 远程 SSH 操作**绝对不要加 `-y`**（`-y` = 直接 `netplan apply`；网关/网卡写错就当场断连，且再也连不回去）。
- 默认的 **`netplan try` 是安全网**：120 秒内不确认会**自动回滚**。出现确认提示时，先另开一个窗口验证能重连，再按回车。
- 若当前会话不是交互终端，`netplan try` 会失败并提示你去 FinalShell 里手动执行 `sudo netplan try`（配置已写好，不会丢）。
- **首次运行不会生成备份**（备份只在目标配置文件已存在时才做）。兜底手段：`netplan try` 自动回滚 + 随时删掉 `99-cotton-static.yaml`。

### 6.2 选地址：三条必须遵守

1. 必须与现场路由器**同网段**；
2. **避开路由器 DHCP 地址池**；
3. **避开已在线设备**（`ping -c 2 <候选IP>` 无响应，或看路由器后台已分配列表）。

> 两台设备设成同一个静态 IP 会 **IP 冲突**，表现为「时通时不通」——比「IP 变了」更难排查。脚本只用 `ping` 做一次检测，发现不了"当前离线但已固定"的设备。

### 6.3 脚本行为须知（避免"以为没生效"）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 没有走 netplan 分支 | 判定条件是「有 `netplan` **且** 有 `/etc/netplan` **且** NetworkManager **未**运行」；Ubuntu 桌面版常常 NM 在跑 | 脚本会自动改用 `nmcli` 改连接，按提示重连即可 |
| 掩码和我预期的不一样 | 前缀自动取「网卡现有地址的 `/xx`」，取不到才默认 `/24` | 用 `-n <网卡> -g <网关>` 显式指定并核对脚本打印的首行信息 |
| `netplan try` 直接退出/报错 | 当前会话非交互式 | 在 FinalShell 里手动执行 `sudo netplan try` |
| 提示配置文件权限问题 | netplan 要求 600 | 脚本已自动 `chmod 600`；手动改时别忘 |
| 提示「目标 IP 与当前 IP 相同」 | 你填的就是它现在拿到的地址 | 正常，这只是把 DHCP 方式改成静态（**零冲突风险**，推荐） |

### 6.4 网络变化后必须做的事

- **搬机 / 换网络（换路由器、换网段）**：静态 IP 就不再成立，先恢复 DHCP 再重新设：
  ```bash
  sudo rm /etc/netplan/99-cotton-static.yaml && sudo netplan apply
  ```
- **改完 IP**：App 里的地址要同步改一次，或点「自动搜索服务器」重扫。
  换服务器地址后需**重新登录**（旧 token 属于上一台服务器）。

### 6.5 现场其他坑

- **手机与服务器必须在同一 `/24`**。路由器若开了 **AP 隔离（客户端隔离）**，「自动搜索」会全部失败 → 只能手填地址（同样要求两机同网段可达）。
- 「自动搜索」会产生 **254~762 次并发请求**（并发 48、单次超时 1.2s，实测 3~8 秒出结果），个别企业网络可能触发安全告警；必要时只用手动填写。
- **共用电脑**：本项目部署手册的原则是「不改网络设置」，本方案属于**经确认后才执行**的可选项。
- 外网不通**不影响局域网识别**（只有新闻等外网功能受影响），所以 `ping 114.114.114.114` 失败不必惊慌。
- 端口要放行：Linux（默认）由 `deploy-lan.sh` 处理；Windows（备用）需要在防火墙放行 **TCP 8088**（`deploy-lan.ps1` 会追加规则，但不改变防火墙开关）。

### 6.6 备用方案：Windows 部署机做法（图形界面）

设置 → 网络和 Internet → 高级网络设置 → 更改适配器选项 → 右键当前网卡 → **属性** → 双击 **Internet 协议版本 4 (TCP/IPv4)** → 选「使用下面的 IP 地址」：

| 项 | 填什么 |
|---|---|
| IP 地址 | 与现场同网段的空闲地址（例如 `192.168.1.100`） |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | 路由器地址（通常 `192.168.1.1`） |
| DNS | `114.114.114.114` 和 `8.8.8.8` |

> `deploy-lan.ps1` 的第 1.5 步会自动打印当前 IP 并让你确认 `[Y/n]`，避免"部署完才发现不是这个地址"。
> ⚠️ Windows 下模型服务是 **conda 原生进程**（`D:\aconda\envs\YOLO\python.exe`），不随 IP 一起搬——换机器时该环境也要准备好，详见 `docs/on-site-quickcard.md` 的「U 盘离线交付」小节。

### 6.7 一分钟自检（配置完照着念一遍）

```bash
ip -4 -br addr show dev <网卡>        # ① 是不是我设的那个 IP / 掩码
ip route | head -3                    # ② default via 是不是现场网关
ping -c 2 <网关>                      # ③ 网关通不通
curl -s http://127.0.0.1:8088/health  # ④ 后端是否 ok
sudo docker compose ps                # ⑤ mysql / backend / model-service 是否 healthy
```

最后一步用手机浏览器打开 `http://<该IP>:8088/health`，看到 `{"code":200,...,"status":"ok"}` 就算通了；
再进 App「我的 → 系统设置 → 服务器地址」点「保存并测试连接」，提示设置成功即全部完成。
