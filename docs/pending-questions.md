# 棉花识别助手确认与待确认清单

## 已确认

```text
1. 后端技术栈：Spring Boot 3.1 + MySQL + JWT；模型服务为 Flask + PyTorch。
2. 后端项目路径：services/backend。
3. 本地后端默认地址：http://localhost:8080。
4. Docker 生产入口：Android 端直接访问 Spring Boot 后端 API。
5. 登录响应字段：统一响应 data.username 与 data.token，前端也兼容 accessToken/jwt。
6. token 请求头：Authorization: Bearer <token>。
7. 注册字段：username/password。
8. 修改密码接口：POST /auth/change-password，需要登录。
9. 退出登录接口：POST /auth/logout，当前后端无状态返回成功，前端清除本地会话。
10. 识别上传字段名：file，可通过前端环境变量调整。
11. 识别接口：POST /recognition；兼容旧入口 POST /api/v1/upload。
12. 识别记录：GET /recognition/history，需要登录。
13. 删除识别记录：DELETE /recognition/history，支持批量 body: { ids: number[] }。
14. 历史记录点击详情：Android 支持。
15. 服务器地址：v1.1.0 起支持在 App 内配置（`我的 → 系统设置 → 服务器地址`），含「保存并测试连接」与局域网「自动搜索服务器」；换电脑/换 IP 无需重新打包 APK。
16. 新闻数据来源（原第 2 条待确认项）：当前已确定为**内置在前端**（`apps/android/src/data/newsData.ts`，配图随包发布），App 不调用后端 `/news` 接口；后续若要改为后端维护，需要重新确认方案。
17. 目标部署机：**默认 Linux**（Ubuntu 20.04+ / CentOS 7+，模型服务跑在容器里，`deploy-lan.sh` 一键部署）；**Windows 10/11 作为备用方案**保留（模型服务是 conda 原生进程，`deploy-lan.ps1`）。文档见 `docs/deployment-guide.md` 第三章与「附录 B」。
18. 颜色级模型的**预处理口径**与**权重来源**（2026-09-20，依据业务方转来的模型作者原始资料包 `棉花颜色杂质`）：作者推理脚本 `mypredict_cbam.py` 用的是 `Resize(256) + CenterCrop(224) + ImageNet 归一化`，仓库模型服务原先默认 `Resize(320)` 属**训练/推理不一致**，已把默认值修正为 **256**（环境变量 `COLOR_RESIZE_SIZE` 仍可覆盖）；同时用 SHA256 确认包内三个 `.pth` 与仓库内权重**逐字节一致**（`cottonarea_best.pth`≡`fenge_best.pth`、`best.pth`≡`impurityarea_best.pth`），**不需要换权重**。依据与实测数据见 `docs/handoff.md` 第 20 节。
```

## 仍待业务确认

```text
1. token 过期后前端是否只提示重新登录，还是后续增加刷新 token。
2. 新闻来源由谁维护，是否需要后台录入或定时同步外部来源。
3. 新闻封面图是否需要真实图片素材。
4. 识别返回结果是否还要补充更多业务字段，例如颜色级、叶屑等级、置信度、叠加图、检测框、人工复核状态。
5. 识别失败的正式提示文案和客服/排查入口。
6. 是否允许前端上传前自动压缩图片，以及压缩质量要求。
7. 未登录识别记录是否需要登录后自动同步到账号：**当前行为是不合并**——检测记录按账号隔离，未登录（游客）期间的识别只存在本机「游客」缓存，登录后不会并进任何账号；登录 / 注册 / App 启动时会从服务器拉取该账号自己的历史（详见 `docs/handoff.md` 第 16 节）。若业务上要求「游客记录登录后并入账号」，需要另行确认（涉及归属规则、去重与时间戳口径）。
8. 分类标准原始资料和图片的最终来源。
9. 除颜色分级、叶屑等级外，是否还要增加其他标准内容。
10. App 图标、启动页和品牌视觉是否采用当前素材，还是替换为正式设计稿。
11. 主要测试机型、Android 最低版本和未来上架渠道。
12. 置信度的业务期望值：根因已定位并修复——线上颜色预处理与训练不一致（线上 `Resize(320)` vs 训练用 `Resize(256)`），修复后作者 75 张标注测试集上的**中位置信度 0.603 → 0.801**，三张实拍样本由 38.68%/42.15%/57.90% 变为 **51/33.2%、51/63.7%、51/58.9%**（详见 `docs/handoff.md` 第 20 节）。**仍需业务方确认**：① 是否接受该口径（置信度＝模型对该图的把握程度，不等于准确率）；② 该权重在作者自建测试集上准确率只有 **83%**（31 级召回仅 0.54），若验收要求稳定 >99%，必须由业务方提供**带标注的现场实拍图**重训——包里没有训练集，需模型作者配合；③ 是否需要「低置信度（例如 <60%）建议人工复核」的提示与阈值。**「先裁棉花 ROI 再分类」与「多窗口平均」两条路线已实测否决**（前者让标注集一致率从 71/75 掉到 66/75），不要再走。
13. 颜色级参考图已内置 cottoninc.com 官方 Hunter Lab 等级图（`apps/android/assets/reference/color-grade-chart.jpg`，实测 700×802）；显示方式已改为「按容器实测宽度 × 真实宽高比显式算高」，不再依赖 `<Image>` 的 `aspectRatio`（见 `docs/handoff.md` 第 17 节）。若业务方有更权威/更清晰的官方原件，替换该文件即可（注意同步 `StandardsScreen.tsx` 里的默认宽高比 700/802）。
14. 置信度的展示口径（前端可做、后端识别流程不动的前提下）：`confidence` 是颜色级分类模型 7 分类 softmax 的最大值，由模型服务决定，App 不能也不应该改这个数值。可选方案——① 维持现状，只显示百分比；② 数值不变，另加「低于 XX% 建议人工复核」提示；③ 增加解释性文案（说明它表示颜色级分类的把握程度，而非「识别准确率」）。请业务方选定，详见 `docs/handoff.md` 第 15 节；**第 12 条与第 20 节已把「为什么是 30 多」的根因查清并修复**，本节只剩展示方式待定。
```
